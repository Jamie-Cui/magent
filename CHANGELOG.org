#+TITLE: Changelog
#+OPTIONS: toc:2 num:nil

All notable user-visible changes to Magent are recorded here.  Entries are
grouped by release and by ~Added~, ~Changed~, ~Deprecated~, ~Removed~, ~Fixed~,
or ~Security~ when applicable.

Magent follows Semantic Versioning as defined in
[[file:docs/RELEASING.org][docs/RELEASING.org]].  There were no release tags before this changelog was
introduced: version ~0.1.0~ was an untagged development preview, and the first
intentional tagged release is planned as ~v0.2.0~.

* Unreleased

** Added

- Bounded, visible retries for truncated Chat Completions streams before
  assistant text is emitted. ~magent-stream-retry-limit~ defaults to 2; retries
  use the same provider input, retain completed tools, count toward the total
  sampling limit, and are cancelled with the turn. Retry notices survive
  session replay without entering model history. Both clean premature EOF
  and curl partial-transfer errors (exit 18) are covered; transport failures
  are marked before cleanup can dispatch unfinished tool calls.

- ~update_plan~ records validated step revisions in the existing ledger and
  displays them through agent-shell's native ACP plan view, including resume.
- Ordered assistant message phases and opaque OpenAI Responses output items.
  The gptel adapter preserves original message phases, reasoning continuation
  data, and tool calls for live continuation and same-route history replay.

- Provider-neutral thinking control across global defaults, ACP sessions,
  custom-agent frontmatter, and Action agent/Answer Steps. DeepSeek requests map
  explicit modes to the native ~thinking.type~ field; disabling thinking also
  suppresses reasoning effort, while unsupported explicit mappings fail before
  provider dispatch.
- An optional ~magent-action-mode-line-mode~ Customize setting that shows the
  active Action count and exposes each current Step and origin as a tooltip.
- Cross-provider model selection through agent-shell's native ACP model option.
  Magent catalogs every gptel-registered backend/model, keeps selections
  session-local, freezes routes per submission, and supports ~Auto~ fallback to
  agent or gptel defaults.  Child agents may override inherited routes with
  their own explicit model.
- A documented Semantic Versioning policy, public compatibility boundary, and
  repeatable release checklist.
- The initial release baseline: the agent-shell and in-process ACP frontend,
  Magent-owned tool loop, permission and approval controls, durable sessions
  and child-agent jobs, Elisp-native Actions, instruction skills, automatic
  capabilities, Doctor, and trusted context-provider extensions.

** Changed

- Independent conversations now execute concurrently, including multiple
  sessions in one project. Turns within a session retain FIFO ordering.
  Completion, cancellation, and startup failures affect only the exact
  submission; Doctor reports all active conversations.

- Ordinary agent turns with no final answer fail visibly with
  ~empty-completion~ instead of reporting completion. No recovery request is
  added. ~magent-execution-result-completed-p~ replaces the old success-named
  predicate; completion does not establish engineering or test success.
- Reasoning visibility controls displayable reasoning items; provider-native
  replay items remain available independently for correct continuation.
- History replay preserves user goals, completed commentary, and terminal tool
  results from failed and interrupted turns. History limits retain whole turns.
  Existing schema v6 records remain readable without rewriting or inventing
  message boundaries; no persisted fields are removed.
- System instructions request useful opening/progress/decision updates,
  proportionate plans, and evidence-based stopping. Shell guidance explicitly
  preserves test exit status and checks each shell script separately.

- Runtime submissions now contain only queue lifecycle state and one canonical
  request context.  Prompt, request-local agent, tools, skills, model route,
  effort, thinking mode, approvals, observer, and turn identity are frozen once in that
  context, which is the sole input to ~magent-agent-run-turn~.
- Project-local agent, skill, capability, and Action definitions now remain
  keyed by canonical project scope. Request execution resolves the exact
  runtime session scope, eliminating active-overlay registry swaps and the
  parallel skill descriptor cache while allowing concurrent project sessions
  to coexist safely.
- Replaced the Emacs-profile-specific prompt dependency with the generic
  ~magent-context-provider-functions~ extension point. Trusted local providers
  contribute ordered request context without making optional failures fatal to
  the agent turn.
- Restyled the generated documentation as a compact Texinfo-style manual with
  adjacent-page navigation, contents links, and localized language controls;
  synchronized the bilingual onboarding module map with all production
  sources and added build-time validation for page/navigation metadata.
- Tool-call headings now emphasize factual operations instead of repeating
  model-authored reason summaries, while approval and audit records retain the
  richer summary.
- Narrowed ~magent-agent-shell.el~ to Magent's ACP config, the single
  ~magent-start~ compatibility entry, and an isolated temporary context
  compatibility block. Interactive buffers, prompts, queues, slash menus,
  skills, and interrupts now use agent-shell's native commands directly.

** Removed

- Removed the bundled ~/memory-init~, ~/memory-refresh~, and ~/memory-clear~
  Actions and their Emacs-profile implementation. Personal profile memory now
  belongs in user configuration as a context provider and user-layer Actions.
- Removed redundant ~magent-agent-shell-*~ commands for shell creation, prompt
  submission, region/symbol helpers, interruption, Action selection, and
  one-shot skill selection, together with private busy-state recovery and
  request handoff machinery.

** Fixed

- Truncated OpenAI-compatible streams no longer look like empty or successful
  answers merely because curl exited cleanly. The adapter retains the model's
  finish reason, rejects incomplete text/tool streams before tool dispatch,
  and preserves completed operations and failure metadata for resuming.

- Session JSON arrays retain their shape across save/load cycles, including
  singleton content-block arrays, plan entries, and nested journal snapshots.
  This fixes a saved session becoming unreadable after loading and saving it.

- Classify synchronous Doctor provider-start failures at the direct sampling
  boundary. Invalid nil text from gptel configuration now points to the
  selected backend's API key/auth-source callback or proxy configuration
  instead of surfacing only ~Wrong type argument: stringp, nil~.
- Accept Codex-compatible ~SKILL.md~ frontmatter with only ~name~ and
  ~description~, default omitted ~type~ to ~instruction~, tolerate known
  host-only metadata without granting it Magent semantics, and discover both
  user and project-local ~.agents/skills~ roots alongside Magent's native
  skill directories.
- Attribute tool and approval audit records to the request-local agent instead
  of the session's selected agent when Actions, compaction, or child execution
  choose a different agent for one turn.
- Render interactive Doctor preflight, runtime and model-route metadata,
  structured ~TODO~ / ~DONE~ / ~FAIL~ / ~KILL~ tasks, persisted-session and
  related-buffer links, and results in one read-only Org buffer.  Persisted
  sessions use standard Org links so Org-aware actions can follow them.  Retain
  content-level startup visibility while focusing Preflight during confirmation
  and Diagnosis at completion; group debug metadata under Environment, keep
  unstarted failure-path tasks distinct from failed work, and keep successful
  isolated-Action completion messages to one concise line.
- Preserve the user side of interrupted turns in provider context so follow-up
  prompts such as "continue" can recover a request after cancellation without
  replaying an incomplete assistant response.
- Persist provider-reported usage on completed ledger turns, preserve failed
  tool status in ACP fallback notifications, and keep resource-identity race
  failures as one structured tool result instead of nesting their printed
  representation in model-visible output.
- Make ~/doctor~ analyze through the originating session's effective model
  route and the same streaming gptel path as ordinary Magent turns, avoiding
  empty diagnoses caused by an unrelated global route or non-stream response.
- Accept both ~tool~ and ~tool-use~ capability markers from gptel model
  metadata, preventing tool-capable providers such as DeepSeek from being
  rejected before sampling.
- Preserve structured provider error responses before gptel cleanup and report
  runtime failures through ACP errors, so agent-shell shows the actionable
  provider message instead of a generic JSON parse error followed by an unknown
  stop reason.
